# Shophippy — VS Code Project

## How to open in VS Code Desktop

1. Download the ZIP `shophippy-vscode.zip`
2. Unzip it
3. Open VS Code → File → Open Folder → select `shophippy-vscode`
4. Open terminal in VS Code (Ctrl+`):

   npm install
   npm run dev

5. Open http://localhost:3000. The dev command starts the Vite site and quote API.

## Neon quote requests

The quote form stores submissions in the linked Neon Postgres database only after the visitor agrees to be contacted. The database connection stays on the server; do not expose `DATABASE_URL` in browser code.

- `.env.local` is generated by `neon init` and is ignored by Git. Keep it private.
- Run `npm run migrate` after Neon setup to create `public.quote_requests` using the direct `DATABASE_URL_UNPOOLED` connection.
- `npm run dev` starts the app and API. Check the API/database connection at http://localhost:3001/api/health.
- For production, run `npm run build`, then `npm start`; configure `DATABASE_URL` in the host environment.
- `npm run build` copies the embedded standalone site into the production bundle.

## Vercel deployment

The repository-root `vercel.json` builds the Vite app and routes `/api/*` to a serverless function that uses the same quote API as local Express.

You do **not** need a Vercel API key. The app only needs its Neon database connection string, kept as a server-side environment variable.

1. In Neon Console, open the project and click **Connect**. Select the `production` branch and the app's database and role, enable the pooled connection option, then copy the connection string. Keep it private.
2. In Vercel, open the site's project, then **Settings → Environment Variables**. Add a variable named `DATABASE_URL`, paste the pooled Neon connection string as its value (unquoted), and enable it for **Production** (and **Preview** if preview deployments need database access). Do not add it with a `VITE_` prefix.
3. In Vercel **Settings → Build and Deployment**, make sure the Root Directory is `./`. The build command and output directory are already set in the repository's `vercel.json`.
4. Redeploy the latest `main` commit so the new environment variable takes effect. Verify that the deployment homepage loads and `/api/health` reports a connected database.

The quote table must already exist in Neon; run `npm run migrate` locally with the direct `DATABASE_URL_UNPOOLED` connection if it has not been created.

## Admin dashboard (quote-to-production workflow)

Open `/admin` (in production) or `http://localhost:3000/admin.html` (dev). Sign-in uses the `ADMIN_PASSWORD` environment variable (owner role, signed HttpOnly session cookie — never hardcode it in the repo).

Workflow: every website quote submission now creates an immutable request record (`SH-XXXXXXXX` reference, raw submission snapshot) and automatically generates a versioned production pack — executive summary, requirements brief, clarification questions, solution architecture, UX plan, scope of work, internal effort estimate (effort ranges only; pricing requires admin decision), production plan, task backlog, request-specific agent prompts, QA test plan, risk review, and release checklist. Status flows `new → processing → ready_for_review / needs_clarification → approved / rejected`, with every step recorded in an append-only audit log.

Admins can review each request workspace, edit artifacts (saved as new versions), regenerate artifacts, copy/download prompts, export the full ZIP pack (spec folder layout with artifact manifest), assign an owner, approve exact artifact versions (approved versions are locked), or reject with a reason. Requests without a stated timeline pause at `needs_clarification` instead of inventing scope.

Migrations 003–004 add the workflow tables (`quote_artifacts`, `quote_agent_runs`, `quote_audit_events`). Run `npm run test` for the pack-engine test suite (Node built-in test runner).
